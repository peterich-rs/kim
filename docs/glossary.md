# 后台入门词表

学习时遇到不懂的词，先回到这里。和计算机网络课教材用词尽量对齐，但只收本项目会碰到的。

## 程序怎么跑起来

| 词 | 白话 |
|---|---|
| **程序 / 二进制** | 编译出来的可执行文件，例如 `echo-server` |
| **进程** | 操作系统把这个文件跑起来的一次。同一文件可以同时开多个进程 |
| **线程 / 异步任务** | 一个进程里同时干多件事的方式。本项目用 Tokio 的异步任务，一个线程可以伺候很多连接 |
| **端口** | 一台机器上的门牌号。`127.0.0.1:8000` = 本机 8000 号门。同一端口同时只能被一个进程占用 |
| **127.0.0.1 / localhost** | 「这台电脑自己」。本机调试用，外网访问不到 |
| **VPS** | 租来的一台云电脑，有公网 IP |
| **域名 / 子域名** | 给人看的名字。`kim.ainexc.com` 和 `minos.ainexc.com` 可以指向**同一台**机器 |
| **DNS** | 把名字翻译成 IP 的电话簿。Cloudflare 帮你托管这本簿子 |
| **反向代理** | 机器上的门卫（Nginx / Caddy）。外面统一进 443，按域名转到后面不同进程 |
| **HTTPS / WSS** | HTTP 或 WebSocket 套上 TLS。本复刻对外入口用这个；证书由 Cloudflare 签发 |

## 连接与协议

| 词 | 白话 |
|---|---|
| **短连接** | 问一句、答一句、断开。网站常见的 HTTP/1 往往是这种用法 |
| **长连接** | 连上之后一直握着，服务器能**主动**推数据。聊天必须这样 |
| **socket / 插座** | 操作系统给你的「往网上读写字节」的把手 |
| **TCP** | 内核里的可靠字节流协议。有握手、序号、ACK、重传、拥塞控制。应用看到的是**没有消息边界**的字节流 |
| **UDP** | 内核里的数据报协议。有包边界，但可能丢、可能乱序。本项目通信层**不用**它 |
| **QUIC** | 建立在 UDP 之上、自己做可靠流的协议。可以以后做成另一个 `Conn` 实现，业务不用改 |
| **WebSocket** | 先用 HTTP 打个招呼再「升级」成帧，底下仍是 TCP。浏览器能用 |
| **拥塞控制** | TCP 发现网络堵了会自己减速。在**内核**里，不是 `kim-tcp` 实现的 |
| **粘包 / 半包** | TCP 流没有「一条消息」的边界：一次 read 可能拿到半条，或两条粘在一起。必须按长度切开 |

## 本项目自己的词

| 词 | 白话 |
|---|---|
| **帧（Frame）** | 应用层的一整个小包裹：类型（数据/心跳/关闭）+ 内容 |
| **opcode** | 帧类型。数值故意和 WebSocket 对齐，TCP 与 WS 可共用业务逻辑 |
| **channel_id** | 一条连接的临时身份证。不能用用户名代替——同一账号可能两台设备同时在线 |
| **Channel** | 对连接的包装。对外可 clone 的是**写专员的信箱**；读循环是另一专员 |
| **写专员 / 读专员** | 每条连接固定两个异步任务：一人独占 write、一人独占 read。不是绑死某个 OS 线程 |
| **信箱（mpsc）** | 写专员桌上的 FIFO 队列。锁从插座挪到这里，入队顺序 = 发出顺序 |
| **反压** | 信箱满了 `push` 失败或等待，避免慢连接把内存撑爆 |
| **ChannelMap** | 当前进程里所有活着的连接。它的锁只护字典，不护插座 |
| **Conn** | 通信层合同：能读一帧、写一帧。谁实现（TCP/WS/QUIC）业务不管 |
| **Acceptor** | 新连接进来，业务决定「这是谁」，返回 channel_id |
| **Agent** | 业务能对连接做的最小操作：我是谁、推一串字节。不能直接关掉连接 |
| **服务 / 实例** | 服务是角色（聊天服务）；实例是一次具体运行（某 IP:端口）。服务发现登记的是实例 |
| **JWT** | 登录第一帧 `LoginReq.token`。本 Demo 只允许 HS256，claims 是 `acc` / `app` / `exp`。不放 Upgrade URL |
| **Router** | `command` → Handler。Chat 用它处理 `login.signin` / `login.signout` / `chat.demo.echo` / `chat.user.talk` / `chat.group.talk` / `chat.group.create` |
| **dest** | Header 字段。单聊是对方账号，群聊是 group id（本里程碑 base36 字符串，不是 ch22 HTTP Base32） |
| **MessagePush** | 服务端主动推的消息体。command 仍是 talk，`Flag=Push`。`sender` 只在 body 里 |
| **写扩散** | 以后：消息写入每个收件人收件箱。本里程碑 Memory 只记一条，不落盘 |
| **Session** | 一条已登录连接的完整记录（account、channel_id、gate_id…），按 channel_id 存 |
| **Location** | 热路径：account → {channel_id, gate_id}。同一账号第二次登录先查这个再互踢 |
| **Kickout** | 互踢通知。command 仍是 `login.signin`，`Flag=Push`，body 是 `KickoutNotify{channelId}`。网关 hook 先看 Flag 再关旧连接 |

## 小册里的四层

| 层 | 干什么 | 现在有没有 |
|---|---|---|
| 通信层 | TCP/WS 收发帧、连接生命周期 | **有**（本仓库 M1） |
| 容器层 | 找到别的服务并连上它们 | **有**（静态 Naming + Container，M2） |
| 链路层 | 登录、指令路由、会话 | **有**（JWT Accept、Router、Memory 会话、互踢） |
| 控制层 | 单聊、群聊、离线 | **有**在线单聊 / 群聊（fake-chat）；离线以后 |
